# IR-001 — Encoded PowerShell Execution

**Status:** Closed — Controlled Simulation  
**Detection severity:** Medium  
**Environment:** Windows SOC Home Lab  
**Primary telemetry:** Sysmon Event ID 1 via Splunk Enterprise  
**MITRE ATT&CK:** T1059.001 — PowerShell

## Executive Summary
A Splunk scheduled detection identified PowerShell execution containing `EncodedCommand`. The alert was generated by controlled activity created specifically to validate the detection pipeline. I pivoted from the alert into endpoint process telemetry, scoped the surrounding time window, reviewed host/user/process context, and examined process lineage.

The event was confirmed as a **true-positive detection of controlled lab behavior**. The investigation did not identify evidence supporting a claim of real compromise.

## Detection
```spl
index=main "<EventID>1</EventID>" powershell.exe "EncodedCommand"
```

The detection was scheduled every five minutes over a rolling five-minute window and configured to trigger when results were greater than zero.

## Investigation Workflow
1. Confirmed the scheduled alert fired in Splunk Trigger History.
2. Pivoted to the matching Sysmon Event ID 1 process-creation event.
3. Scoped telemetry around the event timestamp.
4. Reviewed endpoint, user, image, command line, and parent-image context.
5. Filtered known Splunk Universal Forwarder helper noise.
6. Compared the remaining events to expected controlled activity.
7. Documented the verdict and limitations rather than treating the detection hit as proof of compromise.

## Key Findings
- **Endpoint:** DESKTOP-KRAO2L9 / CLIENT01 context
- **Account context:** LAB\Administrator
- **Process:** PowerShell
- **Indicator:** `EncodedCommand` in command line
- **Source:** Sysmon process-creation telemetry
- **Alert:** scheduled Splunk detection successfully triggered
- **Classification:** controlled simulation / expected lab activity

## Analyst Assessment
Encoded PowerShell is security-relevant because command encoding can obscure script content and is used by both legitimate automation and malicious tradecraft. Therefore, `EncodedCommand` is a **detection lead**, not an automatic malicious verdict.

In this case, the activity matched the controlled validation exercise. No evidence from the scoped telemetry justified escalating the event as an actual intrusion.

## Production Response Considerations
In a production environment I would:
1. Decode and inspect the complete payload.
2. Validate user intent and endpoint ownership.
3. Review parent/child process lineage and adjacent process creation.
4. Correlate authentication and privilege events for the user/host.
5. Search enterprise-wide for the same payload or command-line pattern.
6. If malicious indicators emerged, isolate the endpoint and contain affected credentials according to the incident-response plan.

## Detection Engineering Takeaway
The exercise validated the full chain: **endpoint telemetry → SIEM ingestion → SPL detection → scheduled alert → analyst pivot → scoped investigation → evidence-based verdict**.
